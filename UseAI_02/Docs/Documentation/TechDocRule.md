# 기술 문서 작성 규칙

> 기능별 기술 문서를 작성 / 검수할 때의 규칙
>
> 기술 문서 작성 양식은 `@Docs\Template\TechDocTemplate.md` 를 참고.
>
> 해당 문서는 공통 규칙과 각 섹션에 대한 작성 규칙을 정의한다.

## 1. 공통

### 저장 위치 / 파일명

- 기술 문서는 `Docs/Tech/` 아래에 둔다.
- 파일명은 기능명을 PascalCase, 영어로 짓는다.
- 예시 :

    ```markdown
    - Docs/Tech/PlayerMovement.md
    - Docs/Tech/DamageSystem.md
    ```

### 작성 범위

- 사용자가 승인한 구현만 서술한다. 계획 중이거나 구현되지 않은 기능은 적지 않는다.
- 모든 서술은 실제 소스코드를 근거로 한다. 브리핑, 작업 보고와 코드가 다르면 코드를 기준으로 하지 않고 사용자에게 보고한다.
- 기존 문서를 갱신할 때는 이번 작업으로 달라진 부분만 수정한다.

### 표기

- 클래스, 메서드, 필드, 에셋 이름은 백틱(`)으로 감싸고 코드와 동일하게 적는다.
- 파일 경로는 `Assets/`부터 적는다.
- 코드만으로 확인할 수 없는 내용은 끝에 `(미검증)`을 붙인다.

## 2. 개요

- 기능이 무엇을 하는지 1~3줄로 적는다.
- 연결된 Issue가 있으면 번호를 적는다. 없으면 "없음"으로 적는다.
- 예시 :

    ```markdown
    ## 개요

    - 플레이어가 WASD 입력으로 평면 위를 이동한다.
    - 연결 Issue : #12
    ```

## 3. 구성 파일

- 기능을 구성하는 스크립트, 프리팹, 에셋의 경로와 역할을 표로 적는다.
- 예시 :

    ```markdown
    ## 구성 파일

    | 경로 | 역할 |
    |---|---|
    | `Assets/Scripts/Player/PlayerMovement.cs` | 이동 입력 처리, 위치 갱신 |
    | `Assets/Input/PlayerInput.inputactions` | Move 액션 정의 |
    ```

## 4. 주요 요소

- 클래스별로 public 메서드와 Inspector에 노출된 필드를 적는다.
- private 멤버는 동작 이해에 꼭 필요한 경우만 적는다.
- 예시 :

    ```markdown
    ## 주요 요소

    ### `PlayerMovement`

    | 구분 | 이름 | 설명 |
    |---|---|---|
    | Inspector | `_moveAction` | Move 액션 참조 (`InputActionReference`) |
    | Inspector | `_moveSpeed` | 이동 속도 |
    ```

## 5. 동작 흐름

- 입력(또는 시작 시점)부터 결과까지의 처리 순서를 번호 목록으로 적는다.
- 각 단계에 담당 클래스 / 메서드를 함께 적는다.
- 예시 :

    ```markdown
    ## 동작 흐름

    1. `OnEnable`에서 `_moveAction`을 활성화한다.
    2. `Update`에서 `_moveAction`의 Vector2 값을 읽는다.
    3. 읽은 값에 `_moveSpeed`를 곱해 위치를 갱신한다.
    ```

## 6. 에디터 설정

- 씬 / 프리팹에서 연결해야 하는 항목과 방법을 적는다.
- 코드로 확인할 수 없는 내용이므로 항목마다 `(미검증)`을 붙인다.
- 설정할 항목이 없으면 "없음"으로 적는다.

## 7. 변경 이력

- 문서를 생성 / 갱신할 때마다 한 줄씩 추가한다.
- 예시 :

    ```markdown
    ## 변경 이력

    | 날짜 | 변경 내용 | 연결 Issue / PR |
    |---|---|---|
    | 2026-11-04 | 문서 생성 | #12 |
    ```
